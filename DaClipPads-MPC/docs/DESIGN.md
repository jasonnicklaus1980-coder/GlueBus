# Da Clip Pads: design notes

## 1. What the MPC plugin environment offers
There is no public MPC plugin SDK. Standalone MPC OS hosts plugins through its own copy of JUCE and reads the list
of third-party plugins from `pluginList-arm` in `MPC.settings`, the route the JV-880 port and the other RadioReady /
GlueBus plugins use. What that gives a plugin, and how Da Clip Pads uses it:

| Question | Answer | Used for |
|---|---|---|
| Plugin format / architecture | VST2 `.so`, 32-bit ARM hard-float (armv7, VFPv3-D16), glibc ≤ 2.34, libc/libm/libpthread only | `make arm`; `package.sh` checks all of this |
| Instrument or effect | Both. `isInstrument="1"` puts it on a plugin track as an instrument (like the JV-880 port) | Registered as an instrument, 0 in / 2 out |
| MIDI in | Yes, through `effProcessEvents`: the track's pads and sequence arrive as MIDI notes, sample-stamped | Clip and slice notes, LEARN, gate note-offs |
| Direct pad access | **No.** No API for pad colours, pad banks or pad presses beyond the MIDI notes | Standard MIDI mapping (see MIDI.md) |
| Tempo / transport | `audioMasterGetTime` (VstTimeInfo): tempo, ppq position, bar start, time signature, playing flag | Beat timeline locked to the host; own clock at the host (or MASTER) tempo while stopped |
| State | `effGetChunk` / `effSetChunk` (the JUCE host saves the chunk with the project) | Full state in a text chunk |
| File access | Plain POSIX file I/O on the SD card | WAVs in `/sdcard/Clips`, kits in `/sdcard/Clips/Kits` |
| UI | No custom drawing. The screen is a TUI.json skin in `/sdcard/Synths/<maker> - VST - <name>`: images, filmstrip knobs, buttons and labels bound to parameters, on up to 16 tabs with Q-Link maps | 6 tabs; all readouts are read-only parameters the plugin pushes with `audioMasterAutomate` |
| Time-stretch / resampling from the host | None | Own granular stretcher; own windowed-sinc resampler |
| CPU / memory | MPC X / Live: 4× Cortex-A17 (RK3288), 2 GB RAM shared with MPC itself. No documented plugin budget | Everything pre-allocated; FX sleep when silent; 320 MB sample budget; skin ≈ 44 MB decoded |

What this means for the requested features:
- **Waveform display:** a skin can't draw arbitrary graphics, so waveforms are built from filmstrip boxes. Each box
  shows two level bars (11 heights each) chosen by the parameter value: 4 boxes (8 bars) per clip thumbnail and
  16 boxes (32 bars) for the editor. The marker row under it is 32 one-colour LED parts.
- **Draggable markers:** the waveform's top and bottom halves are horizontal drag strips bound to START and END (on
  CHOP: slice position and slice select). They drag the marker relative to where it is, like a knob; you can't tap an
  absolute position.
- **Pad colours:** plugins can't set MPC pad LEDs. The state is shown on screen instead.
- **Blinking:** a skin can't animate on its own. The "queued" state is a dashed amber ring that stays until launch.

## 3. Threads
- **Host thread** (setParameter, chunks, screen): edits the clip settings (relaxed atomics, one writer) and posts
  requests to the engine through atomic slots (pad presses, stops, scenes, slice plays, shares, clears).
- **Loader thread:** scans `/sdcard/Clips` and the kits, and loads WAVs. Each load is read, converted to the host
  rate, analysed, then handed to the engine through a per-clip atomic `pending` slot. It also frees retired samples
  3 seconds after the audio thread let go of them. That grace period means the host thread can safely read a
  sample's analysis (CHOP, TRIM, FLIP) through `uiSample`.
- **Audio thread:** engine + readouts. It never allocates, frees, locks or touches the SD card. The one exception is
  a `trylock` on the status text, which it skips if busy.

## 4. Timing
- The timeline is in quarter notes. Every block the host time is read. With SYNC on and the host playing, the
  timeline takes the host's ppq position. A jump (sequence loop, locate) moves every scheduled event by the same
  amount, so pending launches keep their distance.
- A block is cut into segments of at most 32 samples, and also at every MIDI event and scheduled beat, so launches,
  stops, follow actions and scene changes land on their exact sample (tests: MIDI note at sample 100 → sound at
  101; launches within one sample of the bar line).
- **Quantise points:** 1/4, 1/8, 1/8T, 1/16, 1/16T on the beat grid; bars on the host's bar lines. Swing moves the odd
  1/8 or 1/16 steps by (swing − 50%) × 2 steps.
- **Late press:** up to 35 ms after a grid point, a launch starts at once, positioned where it would be had it
  started on the point.
- **Follow actions** run on their beat, or at the sample where a one-shot ends / a loop wraps (within 32 samples).

## 5. Playback
- **Positions are logical:** 0..L in playing order. REVERSE mirrors them onto the sample, and REARRANGE maps them
  through a slice table, so fades, loops and stretch need no special cases.
- **Resample:** cubic Hermite (linear in Eco). Speed = pitch ratio × tempo fit.
- **Stretch:** an anchor moves at the time ratio. Grains (2, or 4 in High) start at the anchor every half (quarter)
  grain and read at the pitch ratio under a Hann window. The output is the window-weighted average, so starts stay
  sharp and time = pitch = 1 is exact. At pitch 1 and time 1 the resample path is used (half the CPU).
- **Stretch To:** time ratio = loop length / (N beats × frames per beat). Auto picks N from 1-64 beats (powers of
  two) closest to the tempo.
- **Clicks:**
  - Starts ramp 0.5 ms.
  - Stops ramp FADE OUT (at least 5 ms).
  - A retrigger moves the old voice to a tail that fades out over 4 ms.
  - A loop wrap spawns a tail from the exact wrap sample, which fades out over XFADE (≥ 2 ms) while the loop start
    fades in.
  - Rearranged slices get 1.5 ms edge fades.
  - Mute, volume, pan and sends are smoothed over 4 ms, and the filter cutoff is smoothed per segment.
  - Tests use a DC clip (the worst case) and a sine with live pitch changes.
- **Sample-rate conversion:** once at load, with a 32-tap Blackman-windowed sinc (256 interpolated phases, cutoff
  0.97 × the lower Nyquist). A 1 kHz tone recorded at 48 kHz plays at 1000.00 Hz with the same level on a 44.1 kHz
  host. If MPC changes rate, the clips are converted again.
- **Headroom:** the mix is float. The master limiter (instant attack, 80 ms release) keeps the output under
  0.966 (−0.3 dBFS). The test runs 8 clips of DC at +6 dB and peaks at 0.966.

## 6. SAMPLER stage
The signal path is a 4th-order anti-alias low-pass (blend), then sample-and-hold at the target rate, then
quantisation to 2-24 bits. QUANTIZE sets how much of that error is kept. After that come a zero-order-hold "DAC"
with a gentle low-pass at the target Nyquist, and asymmetric tanh saturation. Hiss and crackle follow the signal
through an envelope follower, so the stage is silent when nothing plays. The presets are sound targets, not
circuits: "SP Style" = 12-bit / 26.04 kHz without a filter, "MPC Style" = 12-bit / 40 kHz, partly filtered, warmer.

## 7. State
The state is the text format in `State/State.h`: global parameters by key, per-clip fields, and scene masks. It's
saved as the VST2 chunk and restored on project load. Clip files are loaded again from their stored paths.
Restoring and saving again gives the identical text (tested). Kits use the same format; factory presets are
snippets of it (`all.*` / `row<R>.*` apply to every clip / a row).

## 8. Performance
Measured on x86, 10 s of audio (`make test`):
- **16 clips, all time-stretching + filter + sends + sampler + master FX:** about 5% of one core
- **16 clips resampling:** about 2.5%
- **Idle:** about 0.1% (reverb, delay, sampler and master chain sleep once silent; clip channels skip when quiet)

Expect roughly 8-10× those figures on one Cortex-A17 core of a Gen1 MPC: well under one core in the worst case,
but not measured on the device yet. To save CPU:
- set QUALITY to Eco (linear interpolation, 2 grains)
- use Resample instead of Stretch where the pitch doesn't matter
- leave SAMPLER off for clips that don't need it

Memory:
- samples: about 10 MB per stereo minute, with a 320 MB total budget and 6 minutes per file
- skin: about 44 MB of decoded images
- everything else is allocated when the sample rate is set: about 1.6 MB of delay and reverb lines at 44.1 kHz
